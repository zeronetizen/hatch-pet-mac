# HatchPet 免费通道领取

## 这是什么

HatchPet 桌面宠物靠一条「中转通道」接收智能体的状态。官方公共中转
（pet.8529527.xyz）有一批免费通道名额，本 skill 就是替用户去领一条：

- 运行 `scripts/claim.mjs` 向公共中转领取一条通道（无需任何账号/凭证）；
- 脚本拿到通道后**当场写第一条状态完成激活**，然后输出一串配对串；
- 你把配对串原样交给用户，用户粘进 HatchPet App 的配对框，配对结束。

## 前置条件

无。只需要能联网、且有 Node ≥ 18 可运行 `scripts/claim.mjs`（零依赖）。

## 流程

1. 运行：

   ```
   node scripts/claim.mjs
   ```

   （默认连 `https://pet.8529527.xyz`；测试或换服务器时可用环境变量
   `PET_SERVER` 覆盖。）

2. 按退出码与 stdout 分三路处理：

   - **退出码 0（领取成功）**：stdout 有两行，第一行是摘要（通道名），
     第二行是配对串本体，形如 `hatchpet1:xxxx…`。把**配对串整串原样**
     发给用户，并告诉他：打开 HatchPet App，把这一串粘进引导页/设置
     里的配对框，点连接即可。不要改动、不要截断这串。
   - **退出码 2（名额已满）**：stdout 第一行是 JSON
     （`{"ok":false,"state":"full",...}`），后面跟着双路引导话术。
     照话术原样转达给用户，二选一：
     - 去 Telegram 找 **@hatchPetBot**，按任务墙关注几个频道领兑换码，
       回 App 引导页填码兑换；
     - 自建中转：用 **relay-channel-setup** skill 在他自己的
       Cloudflare 上部署一套专属中转（该 skill 的「HatchPet 自建
       变体」一节就是为这条路准备的）。
     不要反复重跑脚本抢名额。
   - **退出码 1（失败）**：stderr 有带状态码的报错。把报错大意转达
     用户（网络问题、服务器异常等），稍后再试。特别地：如果报的是
     「激活失败」，说明通道订上了但第一条状态没写进去——**不要**给
     用户任何配对串；那条预订会在 48 小时后自动过期、名额回池，
     不惩罚，网络恢复后重跑脚本重新领即可。

## 纪律（务必遵守）

- **激活纪律**：通道领取只是「预订」，48 小时内没有第一条真实状态
  写入就会作废、名额回池。本脚本已把「领到后立刻写第一条状态」做
  进流程，不要绕开脚本手工调 `/register` 只拿通道不写状态。
- **配对串按凭证对待**：配对串里含通道钥（base64 只是编码、不是
  加密）。只把它交给用户本人粘进 App；不写进任何仓库、日志文件、
  笔记或公开场合；脚本运行输出除最终配对串外不会出现钥明文，你
  转达时也不要把钥单独拆出来贴。
- **一人一条**：给同一个用户领过一次就够了，不要批量领取囤积。
